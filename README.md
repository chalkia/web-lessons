# Πλατφόρμα εξ αποστάσεως ιδιαιτέρων

Στατική ιστοσελίδα (GitHub Pages) με βάση δεδομένων και είσοδο χρηστών στο Supabase.

## Ρόλοι

- **Διαχειριστής**: εγκρίνει εκπαιδευτικούς, βλέπει και διαχειρίζεται τα πάντα.
- **Εκπαιδευτικός**: κάθε εκπαιδευτικός που γράφεται ξεκινά ως **βοηθητικός** (π.χ. φοιτητής). Συνεργάζεται με εγκεκριμένους εκπαιδευτικούς και βοηθά τους μαθητές τους, αλλά δεν έχει δικούς του μαθητές, μαθήματα ή δωμάτιο και δεν φαίνεται στους γονείς. Όταν ο διαχειριστής εγκρίνει τα πιστοποιητικά του, γίνεται **εγκεκριμένος**: έχει δικούς του μαθητές και βλέπει μόνο αυτούς και τους γονείς τους.
- **Μαθητής / γονέας**: στην εγγραφή διαλέγει «Γονέας ή ενήλικος μαθητής» ή «Μαθητής (ανήλικος)». Μόνο ο πρώτος στέλνει αίτημα συνεργασίας σε εκπαιδευτικό. Ο διαχειριστής μπορεί να αλλάξει το δικαίωμα από τη σελίδα Χρήστες.
- **Γονέας και βοηθός δεν είναι τύποι λογαριασμού.** Είναι σχέσεις ανά μαθητή. Ένας εκπαιδευτικός έχει δικούς του μαθητές και ταυτόχρονα μπορεί να είναι βοηθός σε μαθητές άλλου.

## Τι κάνει

1. **Έγκριση εκπαιδευτικού.** Ο εκπαιδευτικός κάνει εγγραφή, συμπληρώνει αίτηση και ανεβάζει πτυχία (PDF, JPG, PNG, έως 5 MB). Ο διαχειριστής εγκρίνει ή απορρίπτει με σημείωση.
2. **Κατάλογος εκπαιδευτικών.** Οι γονείς και οι ενήλικοι μαθητές βλέπουν μόνο τους εγκεκριμένους και στέλνουν αίτημα συνεργασίας. Ο εκπαιδευτικός το δέχεται ή το απορρίπτει.
3. **Ραντεβού.** Μετά από αποδεκτό αίτημα ο εκπαιδευτικός κλείνει ραντεβού γνωριμίας. Μπορεί επίσης να κλείνει συναντήσεις με τους γονείς των μαθητών του. Φαίνονται στο ημερολόγιο και στην αρχική, με κουμπί «Σύνδεση».
4. **Συνεργάτες.** Οι εγκεκριμένοι εκπαιδευτικοί προσκαλούν άλλους (και βοηθητικούς). Οι βοηθητικοί στέλνουν πρόσκληση σε εγκεκριμένους. Μόνο οι συνεργάτες μπορούν να γίνουν βοηθοί. Δύο βοηθητικοί δεν συνεργάζονται μεταξύ τους.
5. **Μαθητές.** Ο εκπαιδευτικός προσθέτει μαθητή με ονοματεπώνυμο και email. Ο μαθητής εγγράφεται αυτόματα και παίρνει email για να ορίσει κωδικό. Μέχρι τότε φαίνεται «Εκκρεμεί κωδικός» και ο εκπαιδευτικός μπορεί να στείλει το email ξανά. Συνδέει επίσης τους γονείς και τους βοηθούς με email. Έχει και ιδιωτικές σημειώσεις που δεν τις βλέπει κανείς άλλος.
6. **Ομαδικά μαθήματα.** Ένα μάθημα έχει έναν ή περισσότερους μαθητές. Η παρουσία (προγραμματισμένο, πραγματοποιήθηκε, απουσία, ακυρώθηκε) ορίζεται ξεχωριστά για τον καθένα.
7. **Ώρες υποστήριξης.** Ο εκπαιδευτικός αναθέτει στον βοηθό δική του ώρα για συγκεκριμένους μαθητές. Μετριέται ξεχωριστά.
8. **Ημερολόγιο = παρουσιολόγιο**, με σύνοψη ωρών ανά μαθητή και ανά βοηθό. Ο καθένας βλέπει μόνο ό,τι τον αφορά.
9. **Δωμάτιο σύγχρονης διδασκαλίας.** Κάθε εκπαιδευτικός βάζει τον σύνδεσμο του δωματίου που θέλει (Meet, Zoom, Jitsi, Teams κ.λπ.). Όλοι μπαίνουν με το κουμπί «Σύνδεση», που ανοίγει νέο παράθυρο. Ένα μάθημα μπορεί προαιρετικά να έχει δικό του σύνδεσμο.
10. **Προσωπικό ημερολόγιο** για κάθε χρήστη.

Επόμενη φάση: σημειώσεις ως σύνδεσμοι προς Google Drive (για να μην φορτώνεται αποθηκευτικός χώρος στο Supabase) και H5P.

## Ρύθμιση

### 1. Supabase

1. Στο Supabase άνοιξε **SQL Editor**.
2. Τρέξε **μία φορά** το `supabase/reset.sql`. Σβήνει τους παλιούς πίνακες. Να το τρέξεις μόνο όσο δεν υπάρχουν πραγματικά δεδομένα.
3. Τρέξε ολόκληρο το `supabase/schema.sql`. Μπορείς να το ξανατρέξεις όποτε θέλεις χωρίς πρόβλημα. Έτσι γίνονται και οι αναβαθμίσεις: δεν χρειάζεται το `reset.sql` ξανά.
4. Στο **Storage** έλεγξε ότι υπάρχει ιδιωτικό bucket `credentials` (το δημιουργεί το schema).
5. Στο **Authentication → URL Configuration** βάλε ως Site URL τη διεύθυνση της σελίδας σου στο GitHub Pages.

### 2. Email πρόσκλησης μαθητή (Edge Function και SMTP)

Η αποστολή email πρόσκλησης χρειάζεται το μυστικό κλειδί υπηρεσίας, που δεν μπαίνει ποτέ στη σελίδα. Γι' αυτό γίνεται από μια Edge Function του Supabase.

1. Dashboard → **Edge Functions** → **Deploy a new function** (Via Editor).
2. Όνομα: `invite-student`. Επικόλλησε όλο το περιεχόμενο του `supabase/functions/invite-student/index.ts`. Άφησε ανοιχτό το «Verify JWT». Πάτα Deploy.
3. Τα κλειδιά (`SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`) τα δίνει αυτόματα το Supabase. Δεν βάζεις τίποτα.
4. **Απαραίτητο: δικός σου SMTP.** Ο προεπιλεγμένος διακομιστής email του Supabase στέλνει μόνο στα μέλη της ομάδας του project και έως 2 μηνύματα την ώρα ([τεκμηρίωση](https://supabase.com/docs/guides/auth/auth-smtp)). Χωρίς δικό σου SMTP οι μαθητές δεν θα λάβουν email. Ρύθμισέ το στο Authentication → Emails → SMTP Settings (π.χ. Gmail με κωδικό εφαρμογής, Brevo, Resend).
5. Authentication → URL Configuration: το Site URL να είναι η διεύθυνση της σελίδας σου στο GitHub Pages.
6. Προαιρετικά: Authentication → Email Templates → «Invite user» και «Reset password», μετάφραση στα ελληνικά.

Με CLI: `supabase functions deploy invite-student`.

Ο μαθητής πατά τον σύνδεσμο, η σελίδα του ζητά να ορίσει κωδικό και μετά μπαίνει κανονικά. Αν ο σύνδεσμος λήξει, χρησιμοποιεί το «Ξέχασα τον κωδικό» στην είσοδο.

### 3. Πρώτος διαχειριστής

Κάνε εγγραφή στη σελίδα και μετά στο SQL Editor τρέξε:

```sql
update public.profiles set role = 'admin' where email = 'το-email-σου';
```

Αυτό δουλεύει μόνο από το SQL Editor. Από τη σελίδα κανείς δεν μπορεί να αλλάξει τον δικό του ρόλο.

### 4. Σύνδεση της σελίδας

Το `js/config.js` έχει το URL του project και το publishable (anon) key. Το key είναι δημόσιο από σχεδίασμα. Την προστασία την κάνουν οι κανόνες RLS στη βάση, όχι το κλειδί.

### 5. GitHub Pages

Settings → Pages → Source: **GitHub Actions**. Το workflow τρέχει πρώτα τους ελέγχους και μετά δημοσιεύει.

## Απόρρητο και πιστοποιητικά

- Τα πτυχία είναι προσωπικά δεδομένα. Τα βλέπουν μόνο ο ίδιος ο εκπαιδευτικός και ο διαχειριστής, με προσωρινούς συνδέσμους διάρκειας 1 ώρας.
- Ο διαχειριστής είναι υπεύθυνος για τη σωστή χρήση τους (ΓΚΠΔ). Να σβήνονται όταν δεν χρειάζονται πια.
- Τα email δεν εμφανίζονται σε άλλους χρήστες. Οι κατάλογοι δείχνουν μόνο ονόματα.
- Οι ιδιωτικές σημειώσεις του εκπαιδευτικού είναι σε ξεχωριστό πίνακα, ώστε να μην τις δει ούτε ο μαθητής, ούτε ο γονέας, ούτε ο βοηθός.

## Έλεγχοι

```
npm run check
```

Ελέγχει σύνταξη, στοιχεία HTML που δεν υπάρχουν, στήλες και πίνακες που δεν υπάρχουν στο `schema.sql`, και ονόματα και παραμέτρους των `rpc`.

Τεστ της Edge Function (ψεύτικοι πελάτες, χωρίς δίκτυο):

```
node tools/edge-test/run.js
```

Τεστ κανόνων πρόσβασης (χρειάζεται τοπική PostgreSQL 16):

```
bash tools/db-test/run.sh
```

## Αρχεία

- `index.html`, `css/style.css`
- `js/core.js`: κοινά βοηθητικά και σύνδεση με το Supabase
- `js/page-account.js`: είσοδος, μενού, πιστοποιητικά, εγκρίσεις, χρήστες
- `js/page-people.js`: μαθητές, συνεργάτες, αιτήματα
- `js/page-lessons.js`: αρχική, δωμάτιο, ημερολόγιο, ώρες υποστήριξης, προσωπικό ημερολόγιο
- `js/app.js`: δρομολόγηση και εκκίνηση
- `supabase/functions/invite-student/`: Edge Function που στέλνει το email πρόσκλησης
- `docs/ROLES.md`: ρόλοι και δικαιώματα (ενημερώνεται σε κάθε αλλαγή)
- `supabase/schema.sql`, `supabase/reset.sql`
- `tools/check.js`, `tools/db-test/`, `tools/edge-test/`
